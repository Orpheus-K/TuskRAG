# 维护统一版本

- 固定现场：记录制品版本、配置摘要、PG 与扩展版本、迁移版本、驱动、模型提供方与嵌入空间；先取证再修改。
- 缩小故障：用 request_id、trace_id、任务 ID、检索 trace 与外部调用结果定位失败边界；不以重启掩盖根因。
- 诊断检索：“没召回”先用检索调试台确认各阶段（过滤、BM25、向量、RRF、重排、阈值）在哪一步丢失，再改参数或代码。
- 脱敏诊断：预览导出范围；剔除密钥与正文；记录复现缺口；不自动外发客户资料。
- 修复根因：修改最小责任模块；添加对应回归或评测用例；不追加无限重试或全局异常吞噬。
- 保持主线：客户差异通过配置、驱动或知识库设置表达；补丁回主线，禁止长期核心分叉。
- 验证升级：检查迁移的“扩展→回填→切换→收缩”阶段、在途任务 schema_version 与扩展升级后的索引状态。
- 演练恢复：PG 与文件成对备份；恢复后执行存储一致性校验与固定评测集比对。
- 核对回退：确认旧程序可读数据；迁移已进入收缩阶段则只能从备份恢复。
- 锁定依赖：更新锁文件、SBOM 与许可证清单；不在生产临时下载依赖或模型。
- 区分授权：准备可审查补丁与部署步骤；本规则不授权生产切换、客户数据外发或不可逆迁移。
