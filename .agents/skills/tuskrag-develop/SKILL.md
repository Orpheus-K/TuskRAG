# 实现最小闭环

1. 定位范围：读取根目录 [AGENTS.md](../../../AGENTS.md)、[代码规则](../../rules/code.md)；涉及存储、检索、权限、模型或接口时读 [架构规则](../../rules/architecture.md)。
2. 对齐契约：定位相关 R/A/T/V 编号、所属模块、现有入口与消费者；明确输入、输出、失败与降级状态及完成条件。
3. 复用能力：搜索既有模块、驱动与成熟上游；只补缺口，不堆备选实现，不引入新常驻服务或进程内模型。
4. 契约先行：API 变更先改 Go 请求/响应类型 → 生成 `contracts/openapi.json` → 生成 `packages/api-client` → 再改前端；解析输出变更先改 `parsed-document.schema.json` 并升 `schema_version`，再改工具与 Go 消费方。
5. 实现变化：保持模块所有权、强类型与单一路径；未定义的情况显式报错，不猜测业务默认值。
6. 验证结果：按 [测试规则](../../rules/testing.md) 检查受影响行为；检索相关改动附评测对比。
7. 交付证据：说明改动、验证、评测结果与未完成项；达到退出条件即停止并按 [笔记规则](../../rules/notes.md) 更新 NOTES。

业务含义无法确定时，保留已完成的独立工作，只澄清阻塞点；不以兼容层同时实现相互冲突的行为。
