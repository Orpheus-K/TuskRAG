# 验证业务不变量

1. 确定基线：读取 [AGENTS.md](../../../AGENTS.md) 与 [测试规则](../../rules/testing.md)；记录待测提交、配置摘要、数据集版本与环境。
2. 选择场景：关联 T/V 编号与评测实验（E1—E7）；读取实现及消费者；区分已实现、待实现和“待定”决策。
3. 构造反例：优先暴露越权证据、跨租户、版本混合、重复块、伪成功、降级未标注与引用错误。
4. 执行检查：使用真实仓库命令；数据库语义用真实 PG；模型用替身服务；隔离外部调用与生产写入。
5. 运行评测：检索相关变更对比基线的 Recall@20、Hit@5、MRR、引用与拒答指标及越权数。
6. 判定结果：逐项给出通过、失败或未运行；标出复现步骤、实际行为与预期差异。
7. 收束验收：纯验收任务不顺手修实现；明确请求修复时修复后重跑相关检查。

拒绝用 mock 成功证明事务或检索正确，用格式检查证明业务完成，或删除失败断言、放宽门槛换取通过。
