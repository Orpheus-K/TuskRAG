# V08 / V09 / T17 云端压测与资源基线报告（2026-11-15）

> 测试范围：20 万分块规模检索（V08）、50 并发检索与 SSE 问答（V09）以及核心进程与 PostgreSQL 内存占用（T17）。
> 模型边界：本次压测使用进程内确定性假模型服务（`/v1/embeddings`、`/v1/rerank`、`/v1/chat/completions`），用于隔离测量 TuskRAG Go 核心、PostgreSQL 17（`pg_search` BM25 + `pgvector` `halfvec(1024)` HNSW）与 SSE 链路自身的吞吐、延迟和内存开销，**不代表外部公网模型 API 的推理耗时**。

## 1. 测试环境与资源隔离

- **宿主机**：`test-host.invalid`（共享云主机，压测期间通过 `nice -n 10 ionice -c2 -n7` 降优先级并与现网容器完全隔离）
- **PostgreSQL 实例**：`test-postgres`（`tuskrag-postgres:verify`，PostgreSQL 17 + `pg_search` + `pgvector`，监听 `127.0.0.1:<db-port>`）
  - 容器配额：`--cpus=1.5 --memory=1536m --memory-swap=2048m --shm-size=256m`
  - 数据库参数：`shared_buffers=512MB`、`maintenance_work_mem=256MB`、`max_wal_size=512MB`
  - 迁移版本：Schema v35（全量 35 个迁移通过）
- **TuskRAG Core API**：`tuskrag.latest`（`TUSKRAG_ROLE=api`，监听 `127.0.0.1:<http-port>`，`lexical_driver=pg_search`）
  - 运行配额：`GOMAXPROCS=2`、`GOMEMLIMIT=384MiB`

## 2. 数据规模与索引构建

- **数据体量**：
  - `document`：200 条
  - `section`：4,000 条
  - `chunk`：200,000 条（`is_current=true`，`access_tags=ARRAY['kb:1:all']`）

- **存储占用（`ANALYZE` 后实测）**：
  - 数据库总大小（`tuskrag_test_verify`）：`1163 MB`
  - `chunk` 表 + 索引：`144 MB`（其中索引 `46 MB`）
  - `chunk_vector` 表 + 索引：`1006 MB`（其中索引 `454 MB`）

## 4. 内存与资源占用（T17）

| 组件 | 空载内存 | 50 并发压测峰值内存 | 压测后回落 |
| --- | --- | --- | --- |
| `tuskrag.latest`（Go API） | `VmRSS = 104,816 kB` (`102.4 MiB`) | `VmHWM = 194,880 kB` (`190.3 MiB`) / 每秒采样最大 `195,380 kB` (`190.8 MiB`) | `VmRSS = 74,864 kB` (`73.1 MiB`) |
| `test-postgres`（PG 17） | `671.8 MiB / 1.5 GiB` (`43.74%`) | `904.5 MiB / 1.5 GiB` (`58.89%`) | `904.2 MiB / 1.5 GiB` |
| **Core + PG 合计峰值** | **~774.2 MiB** | **~1,095.3 MiB (~1.07 GiB)** | **~977.3 MiB** |

- 结论：在 20 万分块 + 50 并发压力下，Go 核心服务与 PostgreSQL 17 合计峰值内存约 **1.07 GiB**，显著低于 `lite` 部署档位（4 GiB）上限，留有充足余量给文档解析子进程与操作系统页缓存。
