# 旧版本清理对照（2026-10-28）

- 范围：R05、R20；隔离 PostgreSQL 17.9 与本地临时文件存储。测试从零迁移至版本 14；独立数据库另验证从 12 升至 13、再升至 14。
- 对照：当前版本的清理请求被拒绝，原件仍存在；切换后的旧版本先标记 `purging`，原件删除后，在任务完成事务中删除该版本、节、块、向量、解析检查点和计划，并写入审计。新版本保持可见。
- 恢复：模拟存储失败后任务可重试；模拟文件删除后租约失效、事务回滚和审计失败时，数据库记录仍为 `purging`，新租约可重放删除并最终完成。缺失或禁用版本保护触发器时，就绪检查和清理均失败；清理进行中尝试恢复旧版本或设为当前版本被拒绝。
- 范围校验：错误任务载荷、过期租约、非规范文件键及仍标记当前的旧块均拒绝删除。测试还验证临时同名表不能替代触发器引用的真实业务表。
- 复现：为本机独立 `tuskrag_test_` 数据库设置 `TUSKRAG_TEST_ADMIN_URL`、`TUSKRAG_TEST_APP_URL`、`TUSKRAG_TEST_MIGRATOR_URL`，在 `services/core` 执行 `go test -p 1 -count=1 -run '^TestPurgeSupersededVersionPostgres$' -v ./internal/ingest`。测试仅创建和删除本次专用数据库与临时目录。
- 限制：仅实现并测试独立的旧版本清理阶段；worker 分发、用户删除整个文档、远端文件驱动及备份恢复尚未完成。
