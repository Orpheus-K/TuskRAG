# 嵌入阶段行为对照（2026-10-28）

关联 R04、R16、A05、A12、A16。样例为合成文本，模型服务为本机 HTTP 替身，不包含客户数据。

| 场景 | 先前状态 | 当前结果 |
|---|---|---|
| Markdown 入库 | 计划暂存后须由调用方直接提供向量 | 真实 Go 解析、分块和 PostgreSQL 暂存后，2/2 子块经替身嵌入并写入向量 |
| 第二批服务失败 | 尚无模型批处理恢复链 | 第一批保留；重试时第一块调用 1 次、第二块调用 2 次，最终 2/2 向量 |
| 分词或用量不一致 | 尚无批处理门禁 | 合成探针不一致时不发送文档；实际批次用量不一致时不写入该批向量 |
| 出域拒绝 / 审计故障 / 租约过期 | 仅独立组件验证 | 拒绝请求并记录审计；审计写入失败不发送请求；过期后不继续探针，迟到结果不写入 |

每次模型请求前核对任务租约、知识库与租户策略、模型配置及凭据快照。计划、存储块内容或现有向量与预期不一致时显式失败。客户端在发送正文前逐条核对 13 个合成分词样例，随后校验每批实际输入的 token 用量；替身使用同一固定 BGE-M3 计数器生成用量，因此此处仅验证控制流程，不证明真实服务的分词兼容性。完成后版本只推进到 `indexing`，当前版本指针仍为空，块和向量均未发布；异租户查询向量数为 0。

复现：对隔离的 PostgreSQL 17 配置 `TUSKRAG_TEST_ADMIN_URL` 和 `TUSKRAG_TEST_APP_URL`，在 `services/core` 运行 `go test -count=1 -run '^TestEmbeddingStage' -v ./internal/ingest`。上述受影响包在真实 PG 和 Linux 下通过 `go test -race`；测试文件 SHA-256：批处理 `9687a8f15464f02c3f5e72c221a56454ba88e374986e3d8aa9103782fb9b710c`；文档链路 `ba9b1369537646678480bbf93f0c86fbb0e200236eefb958b0ba17c521cf1c70`。

真实嵌入服务、服务端 token 用量兼容性、索引、版本原子切换、worker、故障恢复验收和检索指标尚未验证；不能据此判定产品入库完成或 R04、R16 通过。
