第一组对照的父节上限为 20 token。第二个子块包含前一父节的最后一句，因而其页范围包含前一页；结构块和不同标题间不产生该重叠。父节被拆分时保留原标题作为空锚点，伪子节沿用同一标题路径。表头未确认或确认位置无效、表头非首行、无法按支持边界切开的长句或列表项及超限代码块、无正文和其他输入错误均显式失败，不返回部分计划。

测试使用真实 PostgreSQL 17（pgvector 0.8.1、pg_search 0.22.6），从 Markdown 原件上传、Go 原生解析与检查点、规整、构造计划、暂存块，到写入合成向量并推进 `indexing`；相同计划重放得到同一组块 ID，异租户读取块数为 0。另以 Linux 沙箱中的真实 Python CSV 解析器验证大表计划与数据库暂存。当前版本仍为空，块和向量均未设为当前版本；测试未调用实际嵌入服务，也未构建索引或执行检索。Linux 受影响包 `go test -race`、`go vet` 与 golangci-lint 通过。

复现：在 `services/core` 运行 `go test -count=1 -run 'TestBuildPlan|TestBuilt' -v ./internal/ingest`；数据库集成测试须指定隔离的 `TUSKRAG_TEST_ADMIN_URL` 和 `TUSKRAG_TEST_APP_URL`，真实 CSV 解析另需配置 Linux 测试沙箱。Linux 无网络命名空间分别模糊测试 20 秒：长段落 85,948 次输入、列表 43,593 次输入，未发现内容丢失或重排。以 `tokenizers==0.22.1`、固定词表运行[参考计数脚本](../../tests/spikes/tokenizer-hf/structured-reference.py)，得到跨页段落检索输入 33→[19,27]、单个长段落父节 27→[15,15]、长列表父节 48→[25,18,19,10]、表格父节 79→[40,40,40,40]。测试文件 SHA-256：结构测试 `d9db63eb4534b39e89e41cbbc25419a7bf23517cee78fc9790374d3a08fe76e6`；数据库链路测试 `b244553101dc487fc5507d97e463f8a5e80633844111977747874ceb13f7bc8b`。
