# 索引创建与租户计划缓存对照（2026-10-28）

- 范围：R05、R06、R13、A03、A04；PostgreSQL 17.9、pgvector 0.8.1、pg_search 0.22.6，隔离测试库，两个合成租户、各一条记录。测试创建并删除自己命名的临时数据库。
- 通用计划对照：同一物理连接强制通用计划并复用同一预编译 BM25 查询，在两个租户上下文间交替执行 6 次；查询计划计数为 6，错误返回其他租户记录 3 次。自动计划模式在复用同一预编译查询后也观察到跨租户记录。该不安全路径仅用于隔离实验。
- 应用连接：通过 `db.Open` 强制自定义计划；同一物理连接交替租户执行 12 次相同查询，越权记录数为 0。就绪检查拒绝通用计划连接。检索事务仍须本地设置自定义计划并复核权限；连接池代理、完整检索及 T08/T09 未验收。
- 索引：迁移角色并发创建共享部分 BM25 和空间专属 HNSW；3 个并发命令均成功并收敛到同一索引。普通应用角色和超级用户被拒绝；异租户空间、内积距离、错误维度、冲突索引和无效索引均显式拒绝，冲突或无效索引未被自动删除。中断建索引后经人工删除测试索引可重新创建。
- 可见性：事务未提交及回滚时旧可见性不变；提交后新当前块与向量各返回 1，异租户返回 0。应用 HNSW 查询在关闭顺序扫描和排序、强制自定义计划时使用该索引。该实验不实现文档版本原子发布，也不代表正常规模下的计划选择。
- 复现：为本机独立 `tuskrag_test_` 数据库设置 `TUSKRAG_TEST_ADMIN_URL`、`TUSKRAG_TEST_APP_URL`、`TUSKRAG_TEST_MIGRATOR_URL`，在 `services/core` 执行 `go test -p 1 -count=1 -v ./internal/indexing`。测试要求本机 PostgreSQL 管理员具备创建测试数据库和扩展的权限，并只清理本次创建的数据库。
- 限制：没有真实语料、Recall/MRR、延迟、容量、连接池代理或正式产品验收；不构成 pg_search 许可批准。
