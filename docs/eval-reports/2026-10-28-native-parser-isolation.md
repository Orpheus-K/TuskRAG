## 数据与结果

使用 [Markdown/TXT 结构对照](2026-10-28-native-text-structure.md)中的 4 份固定合成样例；基线为相同版本的 Go 原生解析实现，对照为 Linux bubblewrap 与 cgroup v2 内执行正式构建的 Go 二进制。逐个比较完整 `ParsedDocument`：4/4 相同。图片语法、输入限额和非法 UTF-8 的失败类型与基线一致；父进程仍校验 schema 与输出大小。

受限进程的网络命名空间、只读输入与可执行文件、宿主文件及环境变量隔离使用探针验证；缺少原生可执行文件、可执行文件被替换、进程树内存超限均明确失败。Go 子进程实际内存由 cgroup 控制，不使用会阻止 Go 运行时预留虚拟地址的 `RLIMIT_AS`；CPU、文件大小、文件描述符、进程数和墙钟仍受限。

真实工作进程测试在本机隔离 PostgreSQL 和本地模型替身上完成 Markdown 入库，在模型调用期间杀死进程后重领，最终发布且块与向量无重复；CSV、DOCX、XLSX 受限路径也继续通过。此前直接在工作进程解析 Markdown/TXT，不满足 A07；现在没有无沙箱回退。Go 二进制路径指向的文件变更后，当前工作进程拒绝处理并须重启。
