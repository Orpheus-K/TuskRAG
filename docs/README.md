# TuskRAG 设计与开发方案文档集

> 版本：基线 v0.2（2026-10-28；v0.2 将服务端改为 Go 核心，Python 仅保留为一次性解析工具，见 [A02](11-架构决策记录.md#a02)）。本集是设计与开发计划，**不代表任何组件已实现、已测量或已通过验收**。所有资源、延迟、准确率数字均为目标值，须由 [10 评测与质量保障](10-评测与质量保障.md) 和 [09 部署运维](09-部署运维与可观测.md) 中的测量结果确认后才可对外承诺。

## 一、一句话定位

TuskRAG 是面向企业 Agent 的**轻量知识检索底座**：以**单个 PostgreSQL** 作为唯一的业务状态、全文检索、向量检索与任务队列引擎；**Go 核心单二进制**承担全部服务与读路径，**不加载任何模型权重**；文档解析由质量最好的 Python 解析库以一次性工具进程完成；向人（问答控制台）与 Agent（REST / MCP 工具）提供**带权限、带引用、可评测**的检索与问答。

“快、轻、准”的落点：

| 目标 | 设计手段 | 对应文档 |
|---|---|---|
| 轻 | 2 个常驻服务（PostgreSQL + Go 核心）；无 JVM、无 Redis/MinIO/MQ；解析在用完即退的子进程中运行；模型外置 | 03、05、09、11 |
| 快 | 一次 SQL 往返完成过滤+BM25+向量召回；RRF 融合；只对 Top-N 重排；默认单轮检索，Agentic 模式按需开启 | 06 |
| 准 | 结构保真解析 + 页级质量门 + 按需 VLM；标题路径父子分块；混合检索 + 交叉编码重排 + 父块回溯；引用校验与拒答；评测集回归门禁 | 05、06、10 |
| 企业级 | 租户 RLS、知识库 RBAC、文档 ACL 预过滤与出库复核、OIDC SSO、范围化 API Key、审计、数据出域策略、备份恢复 | 07、09 |

## 四、统一术语

| 术语 | 含义 |
|---|---|
| 知识库（KB） | 一组文档 + 一个嵌入空间 + 分块/检索配置 + 成员权限的集合 |
| 文档版本 | 一次上传内容的不可变快照；检索只使用每个文档的“当前版本” |
| 节（Section） | 解析后按标题层级形成的树节点，是父块与目录导航的单位 |
| 块（Chunk） | 检索的最小单位（子块），携带标题路径、页码与所属节 |
| 嵌入空间（Embedding Space） | 模型 + 维度 + 归一化方式的组合；同一空间内的向量才可比较 |
| 访问标签（access_tags） | 文档允许访问的主体集合的反范式化副本，用于检索预过滤 |
| 质量门 | 判断某页原生解析结果是否可信、是否需要 VLM 重解析的规则 |
| 数据出域 | 文档内容或查询被发送到组织边界之外的模型服务 |
| Agentic 模式 | 由 LLM 自主多步调用检索/目录/读节工具完成复杂问题 |

## 五、工程协作方式

开发协作沿用参考项目（agent-project）的“规则 + 技能 + 笔记”方式，但只迁移方法，不迁移其业务：

- 仓库根 [AGENTS.md](../AGENTS.md)：执行约定与真源阅读顺序。
- [.agents/rules](../.agents/rules)：代码、架构、测试、笔记、维护规则，各规则单点维护。
- [.agents/skills](../.agents/skills)：`tuskrag-develop`、`tuskrag-test`、`tuskrag-maintain` 三个技能。
- [.agents/NOTES.md](../.agents/NOTES.md)：当前里程碑快照、证据与下一步；只记录里程碑、阻塞和交接。
