# 12 开发计划与里程碑

## 一、总述

2026-11-07 起的当前主线为问答 MVP：先核对 M1 证据和部署说明，再交付“选知识库 → 单轮提问 → 流式回答 → 引用原文”的完整功能（含拒答、权限复核、超时和取消），然后补齐会话、多轮和反馈，最后进行真实语料、完整用户流程、Linux 部署及基础备份恢复验收。每个功能同时包含后端、页面和验收，不再按内部技术层拆成独立交付阶段。清理任务界面暂后排；M1 尚缺的验收证据保留在 [收束记录](eval-reports/2026-11-07-m1-closure.md)，不将范围收束写成全部验收通过。开发阶段跑定向测试，功能闭环后跑一次同机 Linux 全链路。

本轮开发预览已完成上述主线闭环，真实项目文档、跨页 PDF、页面、Linux 制品与基础恢复结果见 [MVP 验收](eval-reports/2026-11-07-mvp-delivery.md)。各正式里程碑的完整退出条件仍按下表与对应章节判定，不用预览范围替换未完成项。

按“先打通可评测的检索闭环，再加问答，再加企业治理，最后生产化”的顺序推进。每个里程碑结束时必须有可运行的产物与证据（命令、结果、未运行项及原因），并更新 [NOTES](../.agents/NOTES.md)。工期按 2 名全栈开发估算（1 人偏后端/检索，1 人偏前端/工程），仅供排期参考。

## 二、M0 工程骨架与 Spike

**交付**

1. Monorepo：`apps/web`、`packages/{ui,api-client,config}`、`contracts`、`services/core`（Go）、`services/parser`（Python 工具）、`deploy`、`tests/e2e`；从参考项目迁移前端工程配置（Biome、dependency-cruiser、Vitest、Playwright、tsconfig、shadcn Button + Token）与 Go 工程习惯（gofmt、`go vet`、embed 静态资源、SPA 回退）。
2. Go：模块与 `internal/` 包骨架；golangci-lint（含 depguard 层次规则）；sqlc 配置；goose 迁移 embed；`CGO_ENABLED=0` 构建。
3. Python 工具：uv 项目、ruff、mypy（strict）、pytest；`tuskrag-parse version/parse` 命令骨架与 `contracts/parsed-document.schema.json` 初版；无网络运行测试。
4. `deploy/postgres`：PG 17 + pgvector 0.8.x + pg_search 固定版本镜像，初始化 `tuskrag_app`/`tuskrag_migrator` 角色。
5. Go 骨架：配置解析（非法即拒绝启动）、角色启动、`/api/health/live|ready`（含解析工具版本核对）、SPA 托管与深层路由回退、huma 生成 OpenAPI 到 `contracts/openapi.json`。
6. 迁移：第一批表（tenant、app_user、knowledge_base、embedding_space、model_provider、job）+ RLS。
7. CI（GitHub Actions 或企业 CI）：前端检查、Go 检查（含 `-race`）、Python 工具检查、契约生成物一致性、真实 PG 服务容器中的集成测试、Go↔解析工具跨语言测试、镜像构建。
8. 根 `pnpm check` 任务入口串联三种工具链（脚本随实际落地，不预先虚构）。

## 三、M1 入库 + 混合检索 + 调试台 + 离线评测

**后端**

- `kb`：知识库 CRUD、配置修订、文档与版本（R01、R05）。
- `storage`：local FileStore（R02）。
- `jobs`：队列实现（按 A12 结论），租约与重试（R20）。
- `ingest`（Go）：解析工具调用、限额与退出码映射、schema 校验；Markdown 规整；页级质量门（仅评分与报告，VLM 在 M4）；结构化父子分块（R03、R04）。
- `tuskrag-parse`（Python）：DOCX、XLSX/CSV、数字 PDF 驱动与 `render`；每种格式的黄金样例（Markdown/TXT 由 Go 一次性受限子进程处理）。
- `models`：OpenAI 兼容嵌入与重排客户端、超时、限流、错误分类；模型替身服务（测试用）（R16）。
- `index`：chunk/section/chunk_vector 写入、原子版本切换、部分 HNSW 索引管理、pg_search 驱动（R05、R06）。
- `retrieval`：混合召回 SQL、RRF、重排、阈值、调试 trace（R06、R10）。
- `eval`：评测集导入（JSONL）、运行、指标计算、报告（R11）。
- 临时身份：单租户 + 本地管理员（完整身份在 M3）。

**前端**

- 应用框架：布局、主题切换、路由、Query Client、错误边界。
- 知识库列表/创建；文档页（上传、进度、版本、失败原因）；文档详情（Markdown、节树与块、解析报告）。
- 检索调试台（四列对比、参数、设为期望答案）。
- 评测页（运行与指标表，逐题结果）。

**数据**：建立 `synthetic-zh` 评测集（≥ 60 题，含表格与无答案题）。

**退出条件**：T01、T04、T05 通过；T13 后端流程通过（UI 可在 M2 补）；E1—E4 基线报告；V08（20 万块）首测数据回写 04 容量表。

## 四、M2 问答与引用

**退出条件**：T06、T07、T12 通过；首 token p95 在替身 LLM 下 ≤ 目标；生成指标基线建立。

## 五、M3 企业治理

- `identity`：多租户、OIDC（PKCE）、本地账号限制、用户组（claim 映射 + 手工）、服务端会话与 CSRF（R12）。

- 前端：登录、成员与角色、文档 ACL 编辑、API Key 管理、审计查询、模型提供方管理与连通性测试。

**退出条件**：T08—T10、T20 通过；V04、V05、V06、V11 通过（真实 PG，含并发竞态）。

## 八、工作分解原则

- 每个 PR 是“最小完整变更”：含实现、测试、契约与受影响文档；关联 R/A/T/V 编号。
- 契约优先：后端改 API → 重新导出 `contracts/openapi.json` → 重新生成 `api-client` → 前端消费；CI 校验三者一致。
- 驱动先写契约测试，再写实现；两种 Lexical 驱动共用测试。
- 评测门禁从 M1 末开始生效，此后所有影响检索的 PR 必须附评测对比。

## 九、风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| pg_search AGPL 不被法务接受 | 默认 BM25 驱动不可用 | M0 先评估；兼容驱动作为现成退路；E4 量化损失 |
| pg_search 过滤下推或中文分词不达预期 | 召回不足或延迟高 | S1 Spike 尽早验证；必要时 BM25 只在 kb 维度过滤、权限交给出库复核 + 扩大 TopK |
| 原生 PDF 解析在复杂版面上质量差 | “准”受损 | 质量门 + VLM；收集坏样本进评测集；A06 重审条件 |
| 外部模型延迟/限额 | “快”与并发目标失败 | 内网模型节点；查询嵌入缓存；限流与显式降级；部署前测量 V10 |
| 评测集缺乏真实样本 | 门槛失真 | M1 前请业务方提供 ≥ 2 个真实知识库与问题（脱敏） |
| 撤权刷新大批量块导致锁与膨胀 | 性能抖动 | 分批更新、出库复核兜底、维护窗口 VACUUM |
| 跨语言契约漂移（Go ↔ 解析工具） | 入库失败或静默丢字段 | JSON Schema 双侧校验；`schema_version`；工具版本在 ready 检查核对；跨语言测试进 CI |
| Go 侧中文分词/token 计数与服务端不一致 | BM25 召回或分块上限偏差 | S5 Spike 验证；以服务端用量校准 |
| 内存超预算 | “轻”目标失败 | Go `GOMEMLIMIT`；解析一次性子进程；T17 实测后调整 |

## 十、首发形态与待决问题

首发形态确定为客户内网私有化；是否扩展为自有 SaaS 尚未确定。向客户交付组件时的许可评估见 [许可证盘点](../deploy/licenses/README.md)。

待决问题：

1. 默认模型提供方与是否允许数据出域；是否已有内网模型网关。
2. 首批知识库的文档类型分布（扫描件比例、旧版 Office 比例、表格密度）。
3. 企业身份源（OIDC 提供方名称与组信息来源）。
4. 需要对接的外部 Agent 平台（是否都支持 MCP，或只需 REST）。
