# 06 检索与问答

## 一、总述

默认路径是**单轮混合检索**：一条 SQL 内完成权限预过滤 + BM25 召回 + 向量召回 + RRF 融合，然后只对 Top-N 调用交叉编码重排，再做父节回溯与上下文打包。复杂问题使用显式的 Agentic 模式，或由外部 Agent 经 MCP 自行编排（[A09](11-架构决策记录.md#a09)、[A10](11-架构决策记录.md#a10)）。

## 二、检索流水线

| 阶段 | 默认参数（按知识库可配） | 失败时 |
|---|---|---|
| 1 主体解析 | 用户/Key → `principal_tags`（`u:{id}`、`g:{id}`、`kb:{id}:all` 等） | 失败即 401/403 |
| 2 查询预处理 | 去除多余空白；多轮时由 LLM 改写为独立问题（可关） | 改写失败 → 使用原问题并在 trace 标注 |
| 3 查询嵌入 | 查缓存 → 外部嵌入 | 失败 → 若配置 `lexical_fallback=true` 则仅 BM25 并标注 `degraded: ["vector"]`，否则 503 |
| 4 混合召回 | BM25 Top50 ∥ 向量 Top50，`hnsw.ef_search=100`，迭代扫描 | DB 错误 → 500 |
| 5 RRF 融合 | `score = Σ 1/(k + rank)`，k=60；BM25/向量权重 1:1 | — |
| 6 重排 | Top30 送交叉编码器（默认 bge-reranker-v2-m3） | 失败 → 按 `rerank_fallback` 显式失败或返回 `degraded: ["rerank"]` |
| 7 阈值 | 重排分 < `min_score`（按评测集校准）丢弃 | — |
| 8 上下文组装 | 取 Top8；父节回溯；相邻合并；去重；token 预算 | — |
| 9 出库复核 | 按当前 ACL 版本复核每个文档 | 不通过的证据移除并审计 |

降级必须出现在响应体 `degraded` 字段与 trace 中，前端显式提示（[13](13-接口契约概要.md)）。

当前已实现单知识库 BM25、向量召回、RRF、外置 `/rerank` 重排及调试 trace。重排支持已登记提供方、模型、Top-N 20/30/50 及可选分数阈值；已接入知识库持久化配置和请求覆盖，优先级与配置快照规则见 [13](13-接口契约概要.md)。重排调用检查当前出域策略，模型返回后重新核验当前成员、文档、版本及过滤条件，调试候选也受同一复核约束。仅超时、网络错误、429 和 5xx 可按显式配置降级；非法响应、认证错误和出域拒绝直接失败。未启用重排或发生允许的降级时标记 `degraded: ["rerank"]`、`score_kind: "rrf"`；成功重排使用 `score_kind: "rerank"`。父节扩展、完整文档 ACL、跨库检索与真实模型验收仍未完成，见[重排与评测报告](eval-reports/2026-10-29-m1.md)。

当前检索证据和章节读取仅对数字 PDF 返回物理页码；Markdown、TXT、CSV、DOCX 和 XLSX 的解析单元是逻辑页，不标为物理页。检索结果可打开同一当前版本的章节正文，见[章节读取对照](eval-reports/2026-10-29-section-reading.md)。

## 三、混合召回 SQL（示意）

```sql
-- 在同一事务内：SET LOCAL tuskrag.tenant_id = $tenant;
--               SET LOCAL hnsw.ef_search = 100; SET LOCAL hnsw.iterative_scan = relaxed_order;
WITH lexical AS (
  SELECT c.id, row_number() OVER (ORDER BY bm25_score DESC) AS r
  FROM (
    SELECT id, /* pg_search 打分函数 */ score AS bm25_score
    FROM chunk
    WHERE /* search_text BM25 匹配 $query（jieba） */ TRUE
      AND kb_id = ANY($kb_ids) AND is_current AND NOT disabled
      AND access_tags && $principal_tags
      AND ($doc_tags IS NULL OR doc_tags && $doc_tags)
    ORDER BY bm25_score DESC LIMIT 50
  ) c
),
semantic AS (
  SELECT chunk_id AS id, row_number() OVER () AS r
  FROM (
    SELECT chunk_id
    FROM chunk_vector
    WHERE space_id = $space AND is_current
      AND kb_id = ANY($kb_ids) AND access_tags && $principal_tags
    ORDER BY (embedding::halfvec(1024)) <=> $qvec
    LIMIT 50
  ) v
),
fused AS (
  SELECT id, sum(1.0 / (60 + r)) AS rrf,
         min(r) FILTER (WHERE src = 'l') AS lexical_rank,
         min(r) FILTER (WHERE src = 's') AS semantic_rank
  FROM (SELECT id, r, 'l' AS src FROM lexical UNION ALL SELECT id, r, 's' FROM semantic) u
  GROUP BY id
)
SELECT f.*, c.content, c.search_text, c.section_id, c.document_id, c.page_start, c.page_end
FROM fused f JOIN chunk c ON c.id = f.id
ORDER BY f.rrf DESC LIMIT 30;
```

要点：

- 两路召回都在索引扫描内带过滤；`relaxed_order` 迭代扫描在过滤命中率低时继续扫描直到凑满 Top50，避免“HNSW 先取 50 再过滤剩 3 条”。
- 调试模式额外返回每路的原始分数与排名（R10），常规模式只返回融合结果。
- BM25 的确切操作符与打分函数以锁定版本的 pg_search 文档为准，封装在 Go 的 `LexicalDriver` 接口中；兼容驱动用 `lexical_tokens @@ to_tsquery('simple', $query_terms)` 与 `ts_rank_cd`。
- 查询侧分词：pg_search 使用索引同款 jieba 分词器；兼容驱动在 Go 应用侧用 gse 加载同一 jieba 格式词典切词（入库与查询共用），查询词用 OR 连接，停用词过滤。
- SQL 由 sqlc 生成类型安全的 Go 代码；两路召回在同一语句中执行，避免多次往返。

## 四、重排与阈值

- 输入：查询 + `标题路径 + 子块正文`（截断到重排模型上限）。
- 输出分数仅在同一模型内可比；`min_score` 默认通过评测集无答案问题校准：取使“拒答准确率 ≥ 目标且有答案问题 Hit@5 损失 ≤ 2 个点”的阈值。
- 低延迟选项：Top-N 可降到 20；重排结果不缓存（受权限与版本影响）。
- 不允许把 RRF 分数伪装成重排分数；`degraded: ["rerank"]` 时阈值判定改为“不拒答，但提示证据未重排”。

## 五、上下文组装

本节编号条目为 R07 完整目标。当前已在问答编排层实现：继承知识库 `top_k` 候选池、同一 `section_id` 内按 `ordinal` 相邻块合并与父节回溯（同节命中 ≥ 2 块或节正文 ≤ 1,200 token，且要求该节下全部块均为有效未禁用块；否则降级为仅合并有效相邻块）、拼接去句末重叠与同表重复表头、相似度 `> 0.95` 去重（基于规范化文本字符 3-gram Sørensen-Dice）、以及基于 BGE-M3 `TokenCounter` 的 `6,000` 标准预算 token 计量与 `96 KiB` 提示词字节护栏打包（整节超剩余预算时优先退回命中子块，基础单元仍超限时截断尾部低分证据并标记 `context_budget`）；会话历史重载使用持久化的有序 `chunk_ids` 复核后确定性重建一致正文，不存第二份副本。BGE-M3 计数器在此用作系统统一上下文预算估计，不冒充外部生成模型的原生 tokenizer。`/api/v1/search` 仍保持返回原始 chunk 候选（`expand_parent: true` 仍返回不支持）。

1. **父节回溯**：同一节被命中的子块 ≥ 2 个，或节正文 ≤ 1,200 token 时，用整节替代子块。
2. **相邻合并**：同一节中 ordinal 相邻的子块合并为连续片段。
3. **去重**：同一文档多个版本不会同时出现（`is_current` 保证）；内容相似度 > 0.95 的片段只保留排名高者。
4. **预算**：默认 6,000 token；按重排顺序装入，超出时截断尾部低分证据，而不是截断单个证据中间。
5. **证据编号**：每个证据分配 `[1]..[n]`，携带 `document_id、version_id、section_id、heading_path、page_start/end`。

## 六、生成与引用

已实现单知识库单轮问答：控制台选库和模型、POST `/answers`、流式回答、校验引用及原文节预览。生成模型由管理员登记，凭据经既有 Vault 加密；当前 Prompt 为 `grounded-v3`，使用 JSON 证据数据及证据的数字编号，限制回答只覆盖资料直接支持的事实，明确否定结论也是可引用的答案。拒答不得带引用；识别到约定拒答前缀后移除后续引用编号并计入非法引用。模型上游 90 秒、整条 HTTP 流 120 秒，最多输出 2,048 tokens；不自动重试生成。每次事件发送前和无输出期间每秒复核当前会话、成员、证据版本及模型出域策略，失效后取消上游并由页面清空部分回答。超时、取消、非法流与连接中断均不展示为完成。

引用预览在目标节前补读同标题路径、同层级的紧邻上节，以显示分块边界保留的重叠原文；两次读取均走当前权限和版本复核。任一读取被拒绝或版本不匹配时隐藏整个预览。该预览补读不改变发送给生成模型的上下文预算。真实文档与模型对照见 [MVP 验收](eval-reports/2026-11-07-mvp-delivery.md)。

当前完成状态由引用与结束原因决定，`unsupported` 和 `truncated` 显式提示；用量只保存网关实际报告值，缺失不推算。会话保存、多轮追问与反馈已接入，见[会话验收](eval-reports/2026-11-07-conversations.md)。追问最多使用最近三轮已完成问答的有界摘要片段，先以 `rewrite-v1` 改写为独立问题，再重新检索；旧引用编号和证据正文不直接复用。改写 20 秒超时、暂时性模型错误或非法结果可回退原问题并标记 `degraded:["rewrite"]`；权限、出域和配置变化直接失败。历史读取及生成过程都复核其全部证据。单轮证据见[验收记录](eval-reports/2026-11-07-cited-answer.md)。

Prompt 结构（系统提示模板版本化，存于配置修订）：

```text
[系统] 只依据<证据>回答；每个事实句末标注 [n]；证据不足时回答“知识库中未找到相关依据”并说明缺什么。
[证据] [1] 《文档标题》› 章 › 节（第 x—y 页）\n 正文 ...
[历史] 最近 N 轮（摘要化，不含旧证据正文）
[问题] ...
```

- 流式输出：SSE 事件 `retrieval`（证据列表）→ `delta`（文本增量）→ `citations`（校验后的引用）→ `done`/`error`（[13](13-接口契约概要.md#二sse-事件)）。
- **引用校验**：生成结束后解析 `[n]`；不存在的编号移除并记录 `citation_invalid` 计数；无任何有效引用且非拒答的回答标记 `unsupported`，前端提示“回答未引用证据”。
- **拒答**：阈值后无证据 → 不调用 LLM，直接返回拒答（省时省钱）；有证据但 LLM 判定不足 → 允许拒答。
- **多轮改写**：仅当存在历史时调用；改写输出须为单句问题，超长或空则回退原问题。
- 会话持久化：消息、所用证据 ID 与版本、模型、耗时、token 用量；不在日志中打印证据正文。

## 七、Agentic 模式与 MCP 工具

### 7.1 工具集（REST 与 MCP 共用同一服务层与权限）

| 工具 | 作用 | 返回 |
|---|---|---|
| `search(query, kb_ids?, filters?, top_k?)` | 执行第二节流水线（不生成） | 证据列表 + 定位 + 分数 + degraded |
| `list_documents(kb_id, query?, tags?, page?)` | 浏览有权限的文档 | 标题、摘要、更新时间 |
| `get_toc(document_id)` | 文档目录树 | 节 ID、标题、层级、页码、可选摘要 |
| `read_section(section_id, max_tokens?)` | 读取一节正文 | Markdown + 定位 |
| `get_neighbors(chunk_id, before?, after?)` | 读取相邻块 | 片段 + 定位 |

### 7.2 内置 Agentic 问答

- 触发：请求 `mode=agentic`，或知识库配置“复杂问题自动升级”（判定规则：多实体比较、跨文档汇总等，由一次轻量 LLM 分类决定，可关）。
- 循环：LLM 规划 → 调用工具 → 观察 → … → 生成；上限默认 6 步、30 s、20k 证据 token；超限时基于已获证据回答并标注 `truncated`。
- 工具结果与普通检索一样经过权限过滤与出库复核；LLM 只能看到工具返回的内容。

### 7.3 MCP

- 传输：Streamable HTTP，挂载于 `/mcp`；认证使用 API Key（Bearer），Key 范围决定可用知识库与工具。
- 工具 schema 维护在 `contracts/mcp-tools.json`，与 REST 共用同一组 Go 请求/响应类型生成，CI 校验一致；MCP 层使用官方 MCP Go SDK。
- 返回内容携带引用定位，便于外部 Agent 原样引用。

## 八、性能预算（完整检索 p95 ≤ 800 ms 的分配）

| 步骤 | 预算 |
|---|---|
| 鉴权 + 主体解析（缓存命中） | ≤ 10 ms |
| 查询嵌入（外部，缓存未命中） | ≤ 200 ms |
| 混合召回 SQL | ≤ 100 ms |
| 重排 Top30（外部） | ≤ 400 ms |
| 组装 + 复核 | ≤ 30 ms |
| 余量 | ≈ 60 ms |

嵌入与重排是主要变量；内网模型节点或就近区域的 API 是达成“快”的前提，须在部署检查清单中测量（V10）。
