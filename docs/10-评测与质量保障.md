# 10 评测与质量保障

## 一、总述

“准”只能由评测证明。TuskRAG 把评测做成产品能力（R11）和开发门禁：任何影响解析、分块、检索、重排、Prompt 的改动都必须跑固定评测集，并与基线对比。

## 二、评测集

| 集合 | 来源 | 规模（建议） | 用途 |
|---|---|---|---|
| `synthetic-zh` | 仓库内合成文档（制度、手册、表格、扫描样张）+ 人工编写问题 | 60—100 题 | CI 回归；不含任何客户数据 |
| `kb-golden` | 每个知识库管理员维护的真实问题与期望文档/节 | ≥ 50 题/库 | 上线前验收、参数调优 |
| `feedback-pool` | 用户 👎 与纠错，经审核后转入 golden | 持续 | 持续改进 |

用例结构：`question`、`expected`（文档 ID + 可选节 ID/页码，可多个）、`answerable`（是否应有答案）、`reference_answer`（可选）、`tags`（精确词、语义改写、表格、跨文档、多轮、无答案）。

题型配比（建议）：精确术语/条款号 20%、语义改写 25%、表格数值 15%、跨节/跨文档 15%、多轮指代 10%、无答案 15%。

## 三、指标与门槛

| 层 | 指标 | 说明 | 初始门槛（M1 建立基线后校准） |
|---|---|---|---|
| 召回（融合后） | Recall@20 | 期望文档/节出现在融合 Top20 | ≥ 0.90 |
| 排序（重排后） | Hit@5、MRR@10、nDCG@10 | 期望证据排名 | Hit@5 ≥ 0.85 |
| 权限 | 越权证据数 | 评测含受限文档与不同主体 | 必须为 0 |
| 生成 | 引用准确率 | 引用的证据确实支持该句（LLM 评审 + 人工抽检 10%） | ≥ 0.90 |
| 生成 | 拒答准确率 | 无答案题正确拒答、有答案题不误拒 | 正确拒答 ≥ 0.80，误拒 ≤ 0.05 |
| 生成 | 无引用回答率 | `unsupported` 比例 | ≤ 0.05 |
| 性能 | 各阶段 p50/p95 | 同批运行记录 | 见 [06 第八节](06-检索与问答.md#八性能预算完整检索-p95--800-ms-的分配) |

当前 Go 指标计算以融合排序计算 Recall@20，以重排排序计算 Hit@5、MRR@10 和二值相关性 nDCG@10。期望项按文档及可选节、页匹配；页码须落在块的页码范围内。每个块和每个期望项最多各计一次，重叠期望采用最大匹配并优先保留靠前排名；重复块仍占排名。无答案题不计入这些检索指标，全部为无答案题时指标为空。该计算已接入检索服务与 `tuskrag eval run/compare`，运行与数据绑定方式见[评测说明](../tests/eval/README.md)。`synthetic-zh` 64 题已运行真实 PostgreSQL + 模型替身冒烟基线，不能替代真实模型 E1—E4 或产品验收，见[报告](eval-reports/2026-10-29-m1.md)。

回归规则：任一主指标较基线下降 > 2 个点即阻断合并，除非 PR 中给出理由并经评审接受、同时更新基线。越权证据数 > 0 永远阻断。

LLM 评审只作为辅助：评审模型、Prompt 版本固定并记录；不以 LLM 评审单独证明发布质量。

## 四、消融实验（M1/M2 必做，用于证明架构取舍）

| 实验 | 对比 | 决策用途 |
|---|---|---|
| E1 | 仅 BM25 / 仅向量 / 混合 RRF | 证明混合必要性，调 RRF 权重 |
| E2 | 有无重排；Top-N = 20/30/50 | 平衡延迟与准确率 |
| E3 | 固定长度分块 vs 结构化父子分块；有无标题路径 | 证明 [A08](11-架构决策记录.md#a08) |
| E4 | pg_search(jieba) vs 兼容驱动 tsvector | 量化兼容驱动的降级幅度（V03） |
| E5 | 原生解析 vs 原生 + VLM 低分页 | 量化质量门收益与成本 |
| E6 | 父节回溯开/关；上下文预算 4k/6k/10k | 生成质量与成本 |
| E7 | 标准模式 vs Agentic 模式（跨文档题） | 决定 Agentic 自动升级规则 |

结果写入 `docs/eval-reports/`（随实现建立），包含配置修订、模型版本、数据集版本与原始结果文件。

## 五、测试分层

| 层 | 工具 | 要求 |
|---|---|---|
| 单元 | `go test`（含 `-race`） | 分块器、质量门、RRF、引用解析、权限标签计算等纯逻辑；用真实样例文件而非 mock 文本 |
| 解析工具 | pytest（无网络沙箱） | 每种格式的样例文件 → `ParsedDocument` 黄金文件比对；恶意样本；输出通过 JSON Schema |
| 跨语言契约 | `go test` + 真实 `tuskrag-parse` 进程 | Go 调用工具、退出码映射、超限终止、schema 校验、版本核对 |
| 驱动契约 | `go test` + 真实 PG（`tuskrag-postgres` 镜像） | Lexical/Vector/FileStore/Queue 驱动共享同一套行为测试；**禁止用 mock 证明数据库行为** |
| 集成 | `go test` + 真实 PG + 模型替身服务 | 替身实现 OpenAI 兼容接口并可注入延迟/错误；不调用真实外部模型 |
| 前端 | Vitest、Playwright | 见 [08 第六节](08-前端架构与交互.md#六测试) |
| 评测 | `tuskrag eval run` | CI 跑 `synthetic-zh`（可用确定性替身嵌入做冒烟，真实模型评测在夜间任务） |
| 性能 | k6 或 locust | V08/V09 |

## 六、技术验证场景（V）

| 编号 | 场景 | 通过标准 |
|---|---|---|
| V01 | worker 在 parsing/embedding/indexing 各阶段被 SIGKILL | 重启后任务重新认领，最终状态正确，无重复块/向量 |
| V02 | 两个 worker 竞争同一任务；租约过期后旧 worker 迟到提交 | 只有一个结果生效；迟到提交因世代不符被拒绝 |
| V03 | Lexical 驱动契约：pg_search 与兼容驱动 | 同一契约测试全部通过；E4 降级幅度记录在案 |
| V04 | 跨租户：未设置 `tuskrag.tenant_id`、错误租户、直接 SQL | 失败或零行；无数据泄露 |
| V05 | 撤权竞态：撤权与检索并发；access_tags 刷新未完成 | 出库复核移除证据；越权数为 0 |
| V06 | 版本切换竞态：切换事务与检索并发 | 结果只来自一个版本 |
| V07 | 恶意文件：zip 炸弹、XXE、超大页数、畸形 PDF、伪装扩展名 | 子进程被限额终止或拒绝，worker 主进程存活 |
| V08 | 规模：20 万 / 100 万合成块 | 记录 SQL 召回 p50/p95、索引大小、内存；对照 [04 容量表](04-数据模型与存储.md#六容量估算) |
| V09 | 并发：50 / 100 个问答会话（替身 LLM 固定延迟） | api 内存、错误率、p95；确认瓶颈不在本服务 |
| V10 | 外部模型异常：超时、429、5xx、错误维度、非法 JSON | 显式失败或标注降级；无伪成功 |
| V11 | 出域策略：deny 下任何外部提供方调用 | 被 `models` 模块拒绝并审计 |
| V12 | 备份恢复（T16）与存储校验 | 一致性检查通过；缺文件被显式标记 |
| V13 | 滚动升级：新迁移 + 旧应用 | 旧应用读写正常直到替换完成 |
| V14 | MCP 与 REST 权限一致性 | 同一主体同一查询结果集合一致 |

## 七、报告证据

每次验证报告包含：提交号、配置摘要、数据集版本、命令、结果（通过/失败/未运行及原因）。文档检查不能作为产品验收证据（同 [测试规则](../.agents/rules/testing.md)）。
