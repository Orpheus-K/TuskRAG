# 05 文档解析与入库

## 一、总述

入库是低频、可慢、可重试的写路径。目标是**结构保真**（标题层级、表格、页码不丢）而不是“抽出文字”。策略为三层：原生解析优先 → 逐页质量门 → 仅对不达标页按需调用 VLM。

语言分工（[A02](11-架构决策记录.md#a02)、[A07](11-架构决策记录.md#a07)）：

| 步骤 | 执行者 |
|---|---|
| 认领任务、限额、启动/终止解析进程、校验输出 | Go worker |
| 读文件 → `ParsedDocument`；PDF 页面渲染为图片 | Markdown/TXT 由 Go 二进制的一次性受限子进程处理；其他已支持格式由 Python 工具 `tuskrag-parse` 一次性子进程处理 |
| 质量门判定、VLM 调用与出域检查、Markdown 规整、分节分块、嵌入、写索引 | Go worker |

`tuskrag-parse` 只做“读”，不做业务判断；这样解析库可以用质量最好的 Python 生态，而策略、权限、并发与状态都留在 Go 中单点维护。

### 1.1 解析工具调用契约

```text
tuskrag-parse parse  --input <file> --mime <mime> --out <dir> --limits <json>   → <dir>/parsed.json
tuskrag-parse render --input <pdf>  --pages 3,7,12 --dpi 180 --out <dir>       → <dir>/page-<n>.png
tuskrag-parse version                                                            → 工具与各驱动版本（写入 parser_profile）
```

- 退出码：`0` 成功；`10` 不支持的格式；`11` 加密；`12` 超限；`13` 文件损坏；其他视为 `internal`。Go 侧将其映射为 `failure_code`。
- 输出 `parsed.json` 必须通过 `contracts/parsed-document.schema.json` 校验并满足大小上限（默认 ≤ 原文件 20 倍且 ≤ 200 MB），否则任务失败。
- stdout 只输出机器可读的进度行（JSON Lines），stderr 只输出不含正文的诊断；Go 侧限制读取长度。
- 目标是在 `ready` 检查中核对工具版本；当前工作进程启动时检查，版本不匹配拒绝启动，运行中版本变化尚不纳入就绪检查。

## 二、格式支持矩阵

下表同时列出已实现的受限子集和目标驱动；当前 CSV、DOCX、XLSX、数字 PDF、Markdown 与 TXT 有解析实现，工作进程已接入受限入库链，完整能力仍待实现。

| 格式 | 默认驱动 | 结构来源 | 备注 |
|---|---|---|---|
| Markdown / TXT | Go 受限子进程（goldmark） | Markdown 标题语法；TXT 按空行和有限的章/节编号规则推断 | 当前支持受限子集，逻辑页不表示物理页 |
| DOCX | python-docx（读取样式、编号、表格） | 标题样式 Heading 1—9、大纲级别 | 当前只支持标题、段落及非嵌套表格；不伪造物理页码 |
| XLSX | python-calamine（读取）+ openpyxl（独立核对和合并单元格） | 每个工作表一节，保留行列顺序 | 当前支持受限子集；计划构造器要求确认表头后按行分组，自动识别尚未实现 |
| CSV | Python 标准库 `csv` | 单张表，首行及后续行按原顺序保留 | 当前支持 UTF-8/UTF-8 BOM；不规则列数报告信号 |
| PPTX | python-pptx | 每页幻灯片一节；标题占位符为节标题 | 备注栏作为附属文本 |
| PDF（数字） | pdfplumber（字符、字号、表格）+ pypdfium2（文本校验） | 书签优先；无书签时按字号推断 | 当前支持受限子集，保留物理页码；跨页表格合并及渲染尚未实现 |
| PDF（扫描/低质量页） | VLM（页图 → Markdown） | VLM 输出的 Markdown 标题 | 受数据出域策略约束 |
| HTML（静态） | Go 抓取（SSRF 防护：禁止内网/回环/元数据地址、限制重定向与大小）→ 工具内 trafilatura 正文抽取 | h1—h6 | 不执行 JS |
| 图片（PNG/JPG） | VLM | — | 无 VLM 时拒绝 |
| DOC/PPT/XLS（旧格式） | 默认拒绝并提示另存为新格式 | — | 可选：一次性 LibreOffice 转换进程（容器 profile `legacy-office`），转换完退出 |
| 加密/受保护文件 | 拒绝，`failure_code=encrypted` | — | 不尝试破解 |

所有驱动输出统一中间表示 `ParsedDocument`（JSON，schema 位于 `contracts/parsed-document.schema.json`）：

```text
ParsedDocument
  schema_version
  pages: [ {no, width, height, blocks:[{type: heading|paragraph|table|list|code|figure, level?, text|cells, bbox?}],
            signals: {char_count, garbled_ratio, missing_tounicode_ratio, image_coverage, table_suspect}} ]
  outline: 可选（来自书签/样式）
  meta: {title, author, created_at, parser_profile}
```

Python 工具只报告每页的原始信号；是否“低分”、是否送 VLM 由 Go 质量门按知识库配置判定。Go 侧再由统一的 `MarkdownAssembler` 生成规范 Markdown 与节树。驱动只负责“读”，分块逻辑与格式无关。

CSV 使用 [Python 标准库 csv](https://docs.python.org/3.13/library/csv.html)；[python-calamine](https://github.com/dimastbk/python-calamine) 用于 Excel/ODF 工作簿。CSV 的 `no=1` 是统一中间表示中的逻辑单元，不表示原文件存在物理页码。当前工具的 `--limits` 可下调 `max_input_bytes`、`max_output_bytes`、`max_rows`、`max_columns`、`max_cells`、`max_field_chars`；分别默认 200 MiB、200 MiB、100,000、1,024、1,000,000、1,000,000。输出仍受原文件大小 20 倍上限约束。

DOCX 当前保留标题层级、段落、超链接文字与表格顺序，按网格展开合并单元格；`no=1` 表示逻辑单元，不表示物理页。编号列表、页眉页脚、批注、脚注、图片、修订和嵌套表格等暂不支持，遇到时显式拒绝。OOXML 解压总量默认 ≤ 1 GiB、压缩比 ≤ 100；另限制包条目、XML 节点和块数量，并使用 defusedxml 拒绝 DTD/实体。加密 OOXML 容器及 ZIP 加密条目返回 `encrypted`。当前解析对照见 [DOCX 结构报告](eval-reports/2026-10-28-docx-structure.md)。

XLSX 当前按工作表顺序生成逻辑页和一级标题，保留原始单元格的行列位置，展开合并单元格，并以字符串输出布尔值、日期和数值；逻辑页号不表示打印页码。两种读取器对单元格值和合并区域进行交叉核对，结果不一致时失败。公式、隐藏工作表或行列、批注、图形、页眉页脚、错误单元格、带自定义数字格式的数值和不支持的包结构会显式拒绝；受保护文件返回 `encrypted`。此子集沿用 OOXML 限额并限制工作表数量，解析对照见 [XLSX 结构报告](eval-reports/2026-10-28-xlsx-structure.md)。

数字 PDF 当前保留逐页标题、段落、规则表格与物理页码；书签必须与对应页面的唯一文本行匹配，无书签时按字号推断标题。两种读取器提取的字符须一致；表格必须由上传者确认首行为表头。加密文件、旋转页、批注、合并单元格及部分明显的多栏或不确定结构显式拒绝；多栏检测依赖版面启发式，尚未证明能识别所有多栏布局。默认最多 2,000 页、每页 100 万字符并受统一块、单元格和输出限额约束；扫描页记录图像覆盖率，质量不达标时进入失败的 `quality_review` 状态，尚无 OCR、VLM 或页级报告。样例与边界见 [PDF 结构报告](eval-reports/2026-10-28-pdf-structure.md)。

Markdown 当前保留标题、段落、GFM 表格、有序/无序列表和无语言标注的代码块；内联强调及链接保留可见文字，链接目标不输出。图片、HTML、脚注、引用块、分隔线、带语言标注的代码块、不支持的嵌套结构和会丢失额外单元格的表格显式拒绝。TXT 按空行分段，独立的“第……章/节”行分别识别为一级/二级标题。两者只接受 UTF-8（可带 BOM），统一换行后生成一个逻辑页。当前 Go 原生路径还限制输入 ≤ 8 MiB、单行 ≤ 65,536 字节、总行数 ≤ 50,000、Markdown 结构标记 ≤ 100,000，并限制 AST 节点和嵌套深度；可通过解析限额 JSON 下调相应限额。解析对照见 [Markdown/TXT 结构报告](eval-reports/2026-10-28-native-text-structure.md)。

Markdown 规整器已能生成节树和 Markdown：以最近的较低级标题为父节，记录标题路径、页范围和块位置；无标题正文使用无标题的独立节。原始文字、表格单元格与坐标保留在结构化块中，Markdown 中的输入文字会转义；代码块为闭合围栏而补充的末尾换行不改变结构化块中的原文。当前对不规则行列表格、书签 outline、图片及七级以上标题显式拒绝，并限制规整输出 ≤ 64 MiB、块数 ≤ 100,000、单元格数 ≤ 1,000,000。计划构造器已连接规整、分块与暂存并接入工作进程，见 [结构对照](eval-reports/2026-10-28-markdown-assembly.md)和[计划对照](eval-reports/2026-10-28-ingest-plan.md)。

## 三、页级质量门

对每页原生解析结果计算：

| 指标 | 含义 | 低分条件（默认阈值，可配） |
|---|---|---|
| 文本密度 | 可见字符数 / 页面面积 | < 每页 50 字且页面含大面积图像 |
| 乱码率 | 非法 Unicode、私有区字符、`(cid:x)` 占比 | > 5% |
| 字体映射缺失 | 无 ToUnicode 的字体字符占比 | > 10% |
| 图像覆盖率 | 图像 bbox 面积 / 页面面积 | > 70% 且文本密度低 |
| 表格可疑度 | 检测到表格线但单元格提取失败或列数不稳定 | 是 |

处理策略（按知识库 `egress_policy` 与 VLM 配置）：

| 情况 | 动作 | 文档状态 |
|---|---|---|
| 全部达标 | 直接分块 | ready |
| 有低分页，VLM 可用且策略允许 | 仅低分页由 `tuskrag-parse render` 渲染（150—200 DPI）→ Go 调 VLM → Markdown；替换该页结果 | ready（报告标注 VLM 页） |
| 有低分页，VLM 不可用或策略禁止 | 低分页以原生结果入库并标记低质量（检索时降权可配），或跳过 | partial，提示原因 |
| 低分页超过上限（默认 200 页/文档） | 不自动送 VLM，等待管理员确认 | partial，`needs_review` |

VLM 调用约束：并发上限、单页超时、单文档费用上限（按页估算）、重试仅限 429/5xx；输出须为 Markdown，校验不过（空、超长、明显复读）时该页标记失败，不静默接受。

## 四、分块策略

### 4.1 结构化父子分块（默认）

1. 由 Go 侧规整后的 Markdown AST（goldmark）构建节树；每个标题形成一个 `section`，`heading_path` 为根到该节的标题序列。
2. 节正文 = 父块。父块上限默认 1,500 token；超出时按子标题或段落切成连续的“伪子节”，保持 `heading_path` 不变。
3. 节内按段落聚合成子块，目标 300—500 token，硬上限 800；只在段落/句子边界切分（中文句末标点、换行、列表项），相邻子块重叠 1 句（≤ 60 token）。token 计数使用与嵌入模型一致的分词器（Go 侧加载模型的 tokenizer 词表，M0 验证与服务端计数一致；不一致时以服务端返回的用量校准上限）。
4. `search_text = 标题路径（以 › 连接） + 换行 + 子块正文`。标题路径进入 BM25 与嵌入，显著改善“第 3.2 条”“报销标准”类查询的召回。
5. 嵌入输入与 `search_text` 一致；重排输入使用 `标题路径 + 子块正文`。

S5 初测中多个 Go tokenizer 候选与 bge-m3 参考结果不一致。现有 BGE-M3 计数器在合成对照中通过逐 ID 检查；工作进程逐样例核对服务端用量，但尚未与实际嵌入服务核对，较低 token 上限的校准流程也未实现；见 [计数报告](eval-reports/2026-10-28-bgem3-counter.md)和 [Spike 证据](../tests/spikes/README.md#s5bge-m3-token-计数候选库不通过)。

段落拆分器接受同一节内连续段落及显式注入的计数器，在句末标点和换行处分组，保留原文、标题路径、页范围与块坐标；相邻块最多重叠一个不超过配置上限的句子，无法同时容纳重叠句与新句时去掉重叠。硬上限 ≤ 800 token，重叠上限 ≤ 60 token；单句无法装入时显式失败。当前还限制单块 ≤ 512 句、计数输入 ≤ 64 KiB、展示 Markdown ≤ 4 MiB、单次处理 ≤ 100,000 句。计划构造器支持长段落按句拆成父节，以及同一节的跨父节句子重叠，不跨表格、列表、代码块或标题；句界规则尚未经真实检索评测，实际嵌入服务计数一致性未验证；见 [段落分块对照](eval-reports/2026-10-28-text-chunking.md)。

父节切分器按连续的完整块分组，保留标题路径与页范围；无正文标题节仍保留。计划构造器先将长段落按句切分、确认表头的表格按行分组、长列表按条款及直接子项切分，再映射为节树及伪子节，衔接子块拆分器，并可交给暂存服务。父节计数输入最多 64 KiB；不能在句界或支持的列表项边界切开的长内容，以及超出父节上限的代码块显式失败，见 [父节对照](eval-reports/2026-10-28-parent-sections.md)和[计划对照](eval-reports/2026-10-28-ingest-plan.md)。

### 4.2 表格

- 小表（≤ 800 token）整体作为一个 `table` 子块，以 Markdown 表格保存。
- 大表按行组切分，每组重复表头与表名；表名/前一段落作为标题路径的一部分。
- 电子表格：每个工作表一节；行组子块额外写入“列名: 值”展开文本供 BM25 匹配（展示仍用表格）。
- 合并单元格展开为重复值，避免列错位。

表格拆分器已按行分组并重复表头，保留表格逻辑行号和页号；调用方须明确确认首行为表头，全空表头和其他表头位置显式拒绝，尚未实现表头自动识别。CSV/XLSX 的检索输入附带已有列名和值，所有候选均由注入的计数器针对完整检索输入计数。单个候选限制 ≤ 800 token、检索输入 ≤ 64 KiB、展示 Markdown ≤ 4 MiB、≤ 512 个数据行；单次输出限制 10,000 块、文本总计 ≤ 64 MiB、包含重复表头的单元格总数 ≤ 1,000,000；单行或表头无法装入时显式失败。GFM Markdown 的首行表头由语法明确；上传时可明确确认文件中所有表格首行为表头，确认结果随版本保存且不可更改。实际嵌入服务计数一致性未验证，见[表格分块对照](eval-reports/2026-10-28-table-chunking.md)和[表头确认对照](eval-reports/2026-10-28-table-header-confirmation.md)。

### 4.3 其他

- 列表与编号条款保持完整（“第十二条”及其款项不拆散，超长时按款拆分并保留条号）。
- 代码块整体成块，不做句子切分。
- 图片：有 VLM 且策略允许时生成说明文本作为 `figure_caption` 块；否则只保留图注文字。
- 页眉页脚：同一文本在 ≥ 60% 页面重复出现的首尾行视为页眉页脚并去除；页码保留为元数据。

列表分块器按顶层条目分组；超长条款仅在其恰有一个直接子列表时按子项拆分并重复条号，保留有序列表编号、页码和坐标。代码分块器保留完整代码和安全围栏；单项或代码超限、其他无法保真的拆分显式失败。两者已接入计划构造与工作进程，见 [结构对照](eval-reports/2026-10-28-structured-chunking.md)。

### 4.4 可选增强（默认关闭，评测证明有效才开启）

| 增强 | 代价 | 开启条件 |
|---|---|---|
| 节摘要（LLM） | 每节一次 LLM 调用 | 启用 Agentic 模式或目录导航时 |
| 块上下文补充（Contextual Retrieval） | 每块一次 LLM 调用 | 评测集 Recall@20 提升 ≥ 3 个点且成本可接受 |
| 自定义分块规则（正则/条款模板） | 维护成本 | 制度、合同类知识库 |

## 五、版本、增量与删除

- 上传时计算 SHA-256：同一文档内内容相同 → 不新建版本，直接返回现有版本；同一知识库内不同文档内容相同 → 提示重复，可选择仍然导入。
- 新版本的块以 `is_current=false` 写入；全部嵌入完成后在**单事务**中：
  1. `document.current_version_id = 新版本`；
  2. 新块 `is_current=true`、旧块 `is_current=false`（chunk 与 chunk_vector 同步）；
  3. 旧版本 `status=superseded`，入队清理任务。
- 失败版本不改变当前版本；用户可在报告中重试或放弃。
- 删除文档：`deleted_at` + 所有块 `is_current=false`（立即不可检索）→ 清理任务删除块、向量与文件。
- 配置变更（分块参数）只影响之后入库的版本；提供“按新配置重建”批量任务，逐文档按上面的版本流程切换。

暂存服务已能在有效任务租约下原子写入节与非当前块，并以 `ingest_plan` 摘要、嵌入空间和配置版本识别重放；输入数据与持久化前的序列化在事务外完成。相同计划返回原块 ID，不同计划、任务载荷不匹配、配置变化、数据缺失和异常访问标签显式失败。当前单次计划最多 10,000 节和 10,000 块，所有文字合计 ≤ 64 MiB、单行文字合计 ≤ 4 MiB、各类序列化数据 ≤ 128 MiB；超过上限须失败。此阶段只支持继承知识库权限的文档；工作进程后续调用嵌入与发布阶段。

发布阶段在任务完成事务中锁定文档，核验当前配置、有效索引、节与块内容摘要、向量、访问标签和旧版本状态，再同步新旧标记、更新版本指针、写审计并为旧版本入队清理。租约失效、审计失败、暂存数据被修改和迟到的旧版本均回滚。清理阶段先将非当前旧版本标记为 `purging`，再删除原件，最后与任务完成一起删除数据库记录；失败可重试，已进入 `purging` 的版本不能恢复为当前版本。两者已接入工作进程；重新上传同格式文件会创建新版本，成功发布前保留生效版本，见[版本更新对照](eval-reports/2026-10-28-version-upload.md)。[发布对照](eval-reports/2026-10-28-version-publication.md)和[清理对照](eval-reports/2026-10-28-version-purge.md)仅覆盖合成版本与隔离数据库。

删除在同一事务中撤下所有当前块和向量、清空版本指针、软删除文档、写审计并安排版本清理。清理任务先使该版本仍在运行的入库租约失效，再删除原件和派生数据；清理失败不会让文档重新可见。当前每次删除最多 10,000 个版本，保留文档软删除记录；清理死信的手动重试和状态界面尚未实现，见[删除对照](eval-reports/2026-10-28-document-deletion.md)。

## 六、入库状态机

```text
queued → parsing → embedding → indexing → ready
                 ↘ partial（有低质量/失败页，可检索部分）
   任一阶段 → failed（failure_code 显式：unsupported_format | encrypted | limit_exceeded | parse_error
                                         | vlm_denied | model_unavailable | timeout | internal
                                         | file_missing | file_corrupt | cancelled | lease_expired）
ready/partial → superseded（被新版本替换）→ purging → 删除
```

- 每个阶段完成写一次进度；重启后从最近完成阶段继续（解析产物先写入临时表/对象，嵌入按 `(chunk_id, space_id)` 幂等 upsert）。
- `model_unavailable` 可重试；`parse_error`、`limit_exceeded` 不自动重试。
- 取消与最后一次租约过期时，任务和文档版本状态在同一事务中推进；取消使租约失效，过期恢复缺少对应领域处理器时显式失败。
- 前端解析报告展示：页数、每页质量分、VLM 页、表格数、节树、警告列表、耗时与模型用量。

## 七、子进程隔离与限额

| 限制 | 默认值 |
|---|---|
| 单文件大小 | 200 MB |
| 页数 | 2,000 页 |
| 解压后总大小（OOXML/zip） | 1 GB，且压缩比 ≤ 100 |
| XML | defusedxml（工具内），禁止外部实体 |
| 子进程内存（Linux：容器 cgroup v2 或 `prlimit`；Windows 开发机：Job Object） | 1 GB |
| 子进程 CPU 时间 / 墙钟 | 300 s / 600 s（Go `context` 超时后杀整个进程组） |
| 网络 | 子进程不需要网络：容器内以无网络命名空间或 bubblewrap 运行；VLM 与 URL 抓取由 Go worker 发起 |
| 文件系统 | 只读挂载输入文件，只可写本任务临时目录 |
| 临时目录 | 每任务独立目录，结束即删除 |

Go worker 每个任务启动一个新的受限解析进程（不复用）；Markdown/TXT 使用 Go 的内部子命令，其他已支持格式使用 `tuskrag-parse`。进程退出即归还全部内存；子进程被杀或超限时任务以 `limit_exceeded`/`timeout` 失败，Go 主进程不受影响。

当前开发实现的 Linux 沙箱使用 bubblewrap、`prlimit` 和 cgroup v2，限制整个进程树的内存、进程数及 CPU 总量；CPU 用量每 100 ms 检查一次。Go 子进程的实际内存由 cgroup 限制，不设虚拟地址空间上限；Python 子进程另设 `RLIMIT_AS`。运行账户需要处在已委派的 cgroup 子树内，且内核与容器安全策略须允许 `clone3` 的 `CLONE_INTO_CGROUP`；缺少这些条件时解析显式失败。默认 Docker 安全设置下解析失败，容器实验所需的放宽设置尚未确定为生产方案。工作进程已接入沙箱；Windows 隔离尚未实现，不能退回无沙箱执行。实验范围与结果见 [S6 证据](../tests/spikes/README.md#s6解析进程隔离)。

## 八、嵌入

- 批量调用（默认每批 32 块，按 token 上限拆批），并发度按提供方限额配置。
- 写入前校验维度与数值（NaN/全零即失败）；按空间 `normalized` 要求做 L2 归一化。
- 嵌入调用失败（429/5xx）按任务重试策略退避；超过上限 → `model_unavailable`。
- 更换嵌入模型（T13）：创建新空间并设 `pending_space_id`，后台为所有当前块生成新向量并建部分索引，完成后单事务切换 `embedding_space_id`，旧空间向量延迟删除；切换前检索继续使用旧空间。

向量暂存服务按租约分批写入，每批最多 128 条；校验块归属、维度、有限值和 halfvec 可表示范围，按嵌入空间配置归一化，重复写入使用同一 `(chunk_id, space_id)` 更新。计划摘要绑定模型、提供方、维度、距离、归一化配置和内容摘要；配置变化或摘要不匹配显式失败。归一化空间在完成前检查 halfvec 的 L2 范数与 1 相差不超过 0.005，以容纳精度舍入。全部块的向量及访问标签核对完成后仅将版本推进到 `indexing`；工作进程后续调用发布阶段。索引由独立运维命令创建，实际模型服务仍未核验。

嵌入阶段已连接暂存计划、模型目录、当前出域策略和拒绝审计：每次模型调用前检查租约及策略，先用 13 条合成样例核对分词，再核对每批实际输入的本地计数与服务端用量；用量缺失或不一致即失败。每批写入前校验数据库块与计划一致，重试只处理缺失向量，过期租约的结果不能写入。工作进程与查询嵌入仅用本地替身服务验证，真实模型服务尚未核验，见[嵌入阶段对照](eval-reports/2026-10-28-embedding-stage.md)和[入库对照](eval-reports/2026-10-28-ingest-worker.md)。
